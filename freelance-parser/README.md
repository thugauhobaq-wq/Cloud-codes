# Парсер заказов с фриланс-бирж → Telegram

Следит за новыми заказами на **Kwork**, **FL.ru**, **Habr Freelance** и **Weblancer**,
отбирает подходящие по твоим фильтрам и присылает в Telegram-канал через несколько
секунд после публикации. Фильтры настраиваются командами бота — без правки файлов
и перезапусков.

На биржах решает скорость отклика, а обновлять четыре вкладки руками весь день
невозможно. Этим и занимается сервис.

```
🆕 Нужен лендинг на Tilda
💰 15 000 – 25 000 ₽  ·  🏷 Разработка сайтов
🌐 Kwork  ·  👥 3 отклика  ·  🕐 2 мин назад

Собрать лендинг по готовому макету, адаптив обязателен…

[ 🔗 Открыть заказ ]
[ ⭐ В избранное ]  [ 🔕 Стоп-слово ]
```

## Что умеет

- **Четыре площадки сразу.** Kwork разбирается через встроенный JSON-стейт,
  остальные — через RSS/Atom.
- **Фильтры из Telegram.** Ключевые слова, стоп-слова, минимальный бюджет,
  площадки, рубрики — всё меняется командами и применяется со следующего опроса.
- **Без дублей.** Заказ, однажды отправленный, не придёт снова даже после
  перезапуска контейнера.
- **Тихий первый запуск.** При инициализации текущая лента помечается
  просмотренной, чтобы не получить сотню сообщений о заказах, которые давно разобрали.
- **Дайджест вместо спама.** Если за один опрос набралось больше восьми заказов,
  придёт один список, а не восемь сообщений подряд.
- **Не долбится в закрытую дверь.** На 403/429 площадка уходит в паузу с
  нарастающим интервалом, а владельцу приходит одно предупреждение, а не поток.
- **Умное совпадение слов.** «бот» находит «бота» и «Telegram-бот», но не «работа»;
  «верстка» и «вёрстка» — одно и то же.
- **Рубрики учатся сами.** Список берётся из того, что реально приходит с бирж,
  а не из зашитого в код перечня, который устаревает.

## Быстрый старт

### 1. Бот и канал

1. Напиши [@BotFather](https://t.me/BotFather) → `/newbot` → получи токен.
2. Создай канал (или используй личку) и **добавь бота администратором** с правом
   публикации.
3. Узнай `chat_id` канала: перешли любой пост из канала боту
   [@userinfobot](https://t.me/userinfobot) — он покажет id вида `-1001234567890`.
4. Узнай свой user id там же — это `OWNER_ID`, только он сможет менять настройки.

### 2. Настройки

```bash
cp .env.example .env
```

Заполни три обязательных поля:

```ini
BOT_TOKEN=123456789:AAaa...
TARGET_CHAT_ID=-1001234567890
OWNER_ID=123456789
```

### 3. Проверка без отправки

```bash
pip install -e .
python -m fparser dryrun
```

Команда сходит на биржи и покажет в консоли, что нашлось и что прошло бы фильтр.
В канал при этом **ничего не уйдёт**. Это самый быстрый способ убедиться, что
площадки доступны с твоего IP.

### 4. Запуск

```bash
docker compose up -d
docker compose logs -f
```

Дальше напиши боту `/start` и настраивай фильтры.

## Команды бота

| Команда | Что делает |
| --- | --- |
| `/status` | Что сейчас настроено, когда был последний опрос |
| `/kw`, `/kw_add питон бот`, `/kw_del бот` | Ключевые слова |
| `/stopwords`, `/stop_add логотип`, `/stop_del логотип` | Стоп-слова |
| `/budget 5000` | Минимальный бюджет (`/budget 0` — снять порог) |
| `/sources` | Включить и выключить площадки |
| `/categories` | Отбор по рубрикам |
| `/last 5` | Последние отправленные заказы |
| `/favorites` | Сохранённые кнопкой ⭐ |
| `/stats` | Сводка за неделю |
| `/check` | Опросить биржи немедленно |
| `/pause`, `/resume` | Приостановить и вернуть рассылку |

Если ключевых слов нет, проходят все заказы, кроме отсеянных стоп-словами,
бюджетом и рубриками.

## Как это устроено

```
sources/     разбор площадок: base (HTTP, ретраи, RSS), kwork, flru, habr, weblancer
storage.py   SQLite: что отправлено, какие фильтры, статистика
filters.py   отбор заказов — чистые функции, без сети и БД
formatter.py сборка сообщения, экранирование HTML
sender.py    отправка с троттлингом и дайджестом
poller.py    цикл опроса, холодный старт, реакция на блокировки
bot.py       команды владельца
```

Один процесс: бот и поллер живут в общем цикле событий. Состояние — SQLite в
`data/`, смонтированном как том, поэтому обновление образа ничего не теряет.

Интервал опроса задаётся `POLL_INTERVAL` (по умолчанию 180 с) и разбавляется
случайным разбросом ±30 %, чтобы запросы не уходили ровно по расписанию.

## Когда биржа поменяет разметку

Рано или поздно это случится — особенно с Kwork, у которого нет публичного API.
Признак: в `/stats` у площадки найдено 0, в логах предупреждение о JSON-стейте.

```bash
python -m fparser probe kwork
```

Команда скачает живую страницу, положит её в `tests/fixtures/` и скажет, сколько
заказов удалось разобрать. Дальше парсер правится по этой фикстуре, а она же
становится тестом, чтобы поломка не повторилась незамеченной.

Kwork разбирается в два захода: сначала встроенный JSON-стейт (оттуда приходят
бюджет, рубрика и число откликов), а если его не нашлось — вёрстка карточек по
ссылкам вида `/projects/<id>`. Второй путь даёт меньше полей, но лента не встаёт.

Если площадка сменила адрес ленты, его не нужно править в коде — достаточно
переменной в `.env`:

```ini
FEED_URL_FLRU=https://www.fl.ru/rss/all.xml
```

## Разработка

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

pytest -q                          # 122 теста на сохранённых фикстурах
ruff check src tests
python -m fparser dryrun --offline # сквозной прогон без сети
```

Тесты не ходят в интернет: ленты и страницы лежат в `tests/fixtures/`, HTTP
мокается через `respx`. Поэтому они одинаково работают и в CI, и там, где биржи
недоступны.

Полезные флаги `dryrun`:

- `--source kwork` — опросить одну площадку;
- `--all` — показать всю ленту, а не только то, чего ещё не видели (удобно при
  настройке фильтров на уже работающем сервисе);
- `--offline` — работать на фикстурах.

## Что стоит знать

- **Адреса RSS-лент** заданы по умолчанию для FL.ru, Habr Freelance и Weblancer,
  но биржи их иногда меняют. Если `dryrun` по площадке возвращает пусто, проверь
  адрес и при необходимости переопредели через `FEED_URL_*` в `.env`.
- **Kwork чувствителен к IP.** С хостингов и облачных адресов он отвечает 403
  чаще, чем с домашнего. Сервис в этом случае сам уходит в паузу и предупреждает;
  лечится `HTTP_PROXY_URL` в `.env`.
- **GitHub Actions по cron для этой задачи плохой вариант** — IP раннеров биржи
  режут почти сразу, и опрос раз в 5–10 минут теряет смысл на фоне того, что
  заказы разбирают за минуты. Поэтому основной режим — постоянный процесс.
- **Бюджет из текста.** Ни одна площадка не отдаёт сумму отдельным полем в ленте,
  она разбирается из формулировок вроде «Бюджет: 5 000 руб.». «до 120 000» —
  это потолок, а не гарантия, и трактуется именно так.
