# Источники заказов

Что и откуда забирает парсер, чего это стоит по надёжности и что из этого
проверено живьём. Файл обновляется после каждого прогона на сервере.

## Сводка

| Источник | Слаг | Как забираем | Нужен ключ | По умолчанию | Хрупкость |
| --- | --- | --- | --- | --- | --- |
| Kwork | `kwork` | скрейпинг JSON-стейта из HTML, запасной разбор карточек | нет | включён | **высокая** |
| FL.ru | `flru` | RSS | нет | включён | средняя |
| Habr Freelance | `habr` | RSS (Atom) | нет | включён | средняя |
| Weblancer | `weblancer` | RSS | нет | включён | средняя |
| Telegram-каналы | `tg` | HTML-страница `t.me/s/<канал>` | нет | выключен | низкая |
| hh.ru | `hh` | официальный API | нет | включён | низкая |
| Freelancehunt | `fh` | официальный API v2 | **да** | выключен | низкая |

«Хрупкость» — про то, насколько вероятно, что источник сломается сам по себе.
Скрейпинг вёрстки ломается при любом редизайне, RSS живёт годами, но адрес
ленты биржа может сменить, документированный API не меняется без объявления.

Выключенными стартуют те, кому без настройки работать нечем: Telegram-каналам
нужен список каналов, Freelancehunt — токен. Иначе сервис писал бы в лог одну
и ту же жалобу каждые несколько минут. Telegram включается сам при первом
`/tg_add`, Freelancehunt — командой `/sources`, когда токен окажется в `.env`.

## Что проверено, а что нет

**Проверено:** разбор каждого источника на сохранённых ответах, отбор по
фильтрам, дедупликация, склейка сообщения, поведение при 403, 404, 429, 500,
обрыве сети, битой разметке и пустом токене. Это 172 теста, они гоняются в CI
и не зависят от доступности площадок.

**Не проверено: ни одна площадка не опрашивалась вживую.** Из окружения
разработки они закрыты сетевой политикой — закрыт даже `example.com`, так что
дело не в защите бирж. Поэтому адреса лент и формат ответов — обоснованное
предположение, а не факт:

| Источник | На чём основан разбор |
| --- | --- |
| `kwork` | известная схема встроенного стейта, ключи ищутся по форме данных, а не по жёсткому пути |
| `flru`, `habr`, `weblancer` | стандартные RSS и Atom, адреса лент по умолчанию |
| `tg` | структура виджета `t.me/s/`: `data-post`, `tgme_widget_message_text`, `<time datetime>` |
| `hh` | [официальная документация](https://dev.hh.ru/) |
| `fh` | [официальная документация](https://apidocs.freelancehunt.com/) |

Первый `dryrun --all` на сервере заменит догадки фактами. После него фикстуры
пересобираются по живым ответам (`probe`), и таблицу выше нужно дополнить
колонкой «проверено вживую».

## Не годятся для парсинга

Пока пусто: решение принимается по результатам первого прогона, а не заранее.
Кандидат номер один — **Kwork**, и вот почему.

Публичного API у него нет. Существующие обёртки ходят в закрытое мобильное API
**по логину и паролю от аккаунта** — это и нарушение правил площадки, и пароль
от биржи в конфиге на сервере. Такой путь не рассматриваем. Остаётся скрейпинг
страницы проектов, а он ломается при любом редизайне и упирается в защиту от
ботов: с серверных адресов Kwork отвечает 403 заметно охотнее, чем с домашних.

Если 403 подтвердится с VPS, у Kwork три исхода: прокси через `HTTP_PROXY_URL`,
выключение командой `/sources` или переезд на канал-агрегатор в Telegram.
Из кода он в любом случае не удаляется: парсер уже написан, и если площадка
подобреет, включить её — одна кнопка.

## Что ещё рассматривалось

- **Upwork** — RSS-ленты заказов закрыты, а API требует одобрения приложения;
  для русскоязычной ниши отдача не оправдывает возни.
- **YouDo, Workzilla** — заказы бытовые, разработки почти нет.
- **Telegram через юзербота (Telethon)** — даёт закрытые чаты и группы, но
  требует аккаунта, номера и хранения сессии на сервере. Веб-версия `t.me/s/`
  покрывает публичные каналы без всего этого, поэтому начинаем с неё.

## Когда источник сломался

Признак — в `/stats` у площадки найдено 0, а в логах предупреждение.

```bash
docker compose run --rm fparser python -m fparser probe kwork
```

Команда скачивает живой ответ, кладёт его в `tests/fixtures/` и печатает,
сколько заказов удалось разобрать. Дальше разбор чинится по этой фикстуре,
а она же становится тестом, чтобы поломка не повторилась незамеченной.

Если сменился адрес ленты, править код не нужно — достаточно переменной
`FEED_URL_*` в `.env`.
