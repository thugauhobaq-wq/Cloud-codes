# Развёртывание ботов

Инструкция для того, кто ставит бота на сервер: [`booking-bot`](booking-bot/),
[`shop-bot`](shop-bot/), [`leadmagnet-bot`](leadmagnet-bot/),
[`freelance-parser`](freelance-parser/), [`botfactory`](botfactory/) и любой
бот, созданный [`botkit`](botkit/). Все они устроены одинаково, поэтому шаги
общие — меняются только имя каталога и содержимое `.env`.

## Что нужно от сервера

| Требование | Значение |
| --- | --- |
| ОС | любая с Docker: Ubuntu, Debian, Alma |
| Память | от 1 ГБ (бот занимает ~150 МБ) |
| Диск | ~1 ГБ: образ 165 МБ плюс база, которая растёт медленно |
| Порты | никаких: боты работают на long polling и сами ходят к Telegram |
| Домен и сертификат | не нужны |

Нужен исходящий доступ к `api.telegram.org`. Входящих соединений бот не
принимает, поэтому пробрасывать порты и настраивать nginx не требуется.

## Установка

```bash
git clone <репозиторий> && cd shop-bot     # или booking-bot, leadmagnet-bot…
cp .env.example .env
nano .env                                   # BOT_TOKEN и OWNER_ID обязательны
docker compose up -d --build
docker compose logs -f
```

Токен даёт [@BotFather](https://t.me/BotFather), ваш user id покажет
[@userinfobot](https://t.me/userinfobot).

В логах при удачном старте:

```
13:23:01 INFO    shop: запускаюсь: Магазин
13:23:01 INFO    aiogram.dispatcher: Start polling
```

Каталог `data/` создаётся сам, права на него выставляются при старте — ничего
делать руками не нужно.

## Проверка, что всё работает

1. Напишите боту `/start` — он должен ответить меню.
2. Отправьте `/admin` — с вашего `OWNER_ID` придёт справка админа.
3. Пройдите короткий сценарий целиком: запись, заказ или выдача материала.
   Владельцу должно прийти уведомление.
4. `docker compose restart` — бот поднимается, данные на месте.

Полезно проверить и офлайн-командами, не запуская бота:

```bash
docker compose run --rm shop python -m shop catalog     # витрина
docker compose run --rm shop python -m shop orders      # заказы
```

`shop` здесь — имя сервиса из `docker-compose.yml`; у остальных это
`booking`, `leadmagnet`, `fparser` и `botfactory`. Команды у каждого бота свои
и перечислены в его README.

## Обновление

```bash
git pull
docker compose up -d --build
```

База лежит в `data/` вне контейнера и переживает пересборку. Схема
дополняется на месте при первом запуске новой версии: например, магазин,
который принимал заказы до появления оплаты, после обновления получает поля
оплаты, не теряя прошлых заказов.

## Бэкап

База — один файл, и снимать копию можно на ходу, не останавливая бота:

```bash
docker compose exec shop python -c "
import sqlite3
src = sqlite3.connect('/app/data/shop.db')
dst = sqlite3.connect('/app/data/backup.db')
with dst:
    src.backup(dst)
"
```

Так копия получается согласованной даже во время записи — этим `.backup`
отличается от `cp`, который может застать базу на середине транзакции.
Готовый файл лежит в `data/backup.db`. Копируйте его к себе хотя бы раз в
сутки: в базе заказы, записи и собранная база подписчиков — восстановить их
неоткуда.

Восстановление: остановить бота, положить файл на место рабочей базы,
запустить снова.

```bash
docker compose stop
cp backup.db data/shop.db
docker compose start
```

## Когда бот молчит

| Что видно | Что случилось | Что делать |
| --- | --- | --- |
| `Не заданы обязательные переменные окружения: BOT_TOKEN, OWNER_ID` | `.env` не заполнен | заполнить и `docker compose up -d` |
| `Unauthorized` в логах | неверный токен | взять токен заново у @BotFather |
| `Conflict: terminated by other getUpdates request` | тот же токен использует второй запущенный бот | оставить один экземпляр: `docker compose ps` на всех серверах |
| `unable to open database file` | каталог `data/` недоступен на запись | проверить, что том не смонтирован только для чтения |
| Контейнер в перезапуске | нет доступа к `api.telegram.org` | проверить сеть сервера; бот перезапускается сам и подхватится, когда связь появится |
| Бот отвечает, админка молчит | `OWNER_ID` чужой | посмотреть свой id у @userinfobot |

Логи: `docker compose logs --tail 100`. Состояние: `docker compose ps`.

## Несколько ботов на одном сервере

Каждый бот — отдельный каталог со своим `.env`, `data/` и
`docker-compose.yml`. Они не мешают друг другу: портов не занимают, имена
контейнеров разные. Ограничение одно — **один запущенный экземпляр на токен**:
два бота с одним токеном отбирают друг у друга обновления, и оба работают
через раз.

## Что проверено

На чистом Docker собраны и запущены образы всех четырёх ботов и обоих
вариантов проекта из `botkit` (в общем репозитории и автономного). Проверено:

- сборка образа с нуля и запуск офлайн-команд в контейнере;
- каталог `data/`, смонтированный с хоста: база создаётся и переживает
  пересборку образа;
- процесс внутри контейнера работает не под root (uid 1000);
- `docker compose up -d` поднимает бота, `docker stop` останавливает его
  мягко — за 0,1 секунды, а не по десятисекундному таймауту;
- незаполненный `.env` даёт понятное сообщение, а не трейсбек;
- недоступный Telegram завершает процесс с ненулевым кодом, и
  `restart: unless-stopped` поднимает бота заново.

Образ `botfactory` проверен без шага `apt-get install git`: в окружении сборки
закрыт доступ к репозиториям Debian. Остальная часть его образа — установка
пакета, права на томе, понижение привилегий — проверена так же, как у других.

Не проверено вживую: работа с настоящим токеном и реальным Telegram — в
окружении, где это собиралось, доступа к `api.telegram.org` нет. Проверьте
первый диалог с ботом сами по разделу «Проверка, что всё работает».
