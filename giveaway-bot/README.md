# giveaway-bot

Telegram-бот розыгрышей: собирает участников, проверяет подписку на каналы и
в назначенный срок сам подводит итоги — честным жребием, который любой
участник может пересчитать и проверить.

Механика, которую заказывают SMM-щики: розыгрыш ради подписчиков работает
только пока люди верят, что победителя не выбрали заранее. Поэтому здесь
жребий не «random.choice», а воспроизводимая процедура: бот публикует зерно,
и по нему результат пересчитывается кем угодно.

## Как это выглядит

Организатор пишет в бот:

```
/new Кофе в подарок | Пачка зёрен 250 г | 2 | 3д | @mychannel
```

Бот заводит розыгрыш, отдаёт карточку с кнопками и готовый текст для поста в
канале — со ссылкой `t.me/бот?start=g12`. Человек жмёт «Участвовать»: бот
проверяет подписку на указанные каналы и выдаёт номер участника. Через три
дня бот сам тянет жребий, публикует объявление с именами победителей и
зерном, пишет каждому победителю лично и сообщает организатору, кто закрыл
личку и до кого не достучаться.

## Честный жребий

Проблема любого розыгрыша: слово организатора против недоверия участников.
Здесь их можно не уговаривать, а дать проверить.

1. В момент подведения итогов бот считает **зерно** — sha256 от номера
   розыгрыша, времени завершения и списка id всех участников. До закрытия
   набора зерно не существует и предсказать его нельзя: любой новый участник
   меняет его целиком.
2. Каждому участнику достаётся **билет** — `sha256(зерно:tg_id)`.
3. Побеждают наименьшие билеты по возрастанию.

Зерно печатается в объявлении. Дальше любой считает свой билет одной строкой:

```python
hashlib.sha256(f"{seed}:{my_id}".encode()).hexdigest()
```

Организатор проверяет весь розыгрыш целиком:

```
python -m giveaway verify 12
```

Команда пересчитывает жребий заново и сверяет с тем, что записано в базе;
несовпадение — ненулевой код возврата. Подмена победителя или перестановка
мест не проходят проверку.

Чего этот способ **не** делает: он не мешает организатору выкинуть участника
из набора до жеребьёвки. От этого защищает публичность списка (`/participants`,
`/export`), а не математика — и честно об этом сказать лучше, чем обещать
невозможное.

## Команды

Участнику:

| Команда | Что делает |
| --- | --- |
| `/start` | приветствие; по ссылке `?start=g12` — сразу карточка розыгрыша |
| `/go` | активные розыгрыши |
| `/my` | в чём участвую и что выиграл |

Организатору:

| Команда | Что делает |
| --- | --- |
| `/new Название \| приз \| 2 \| 3д \| @channel` | новый розыгрыш; обязательно только название |
| `/giveaways` | список со статусами |
| `/g 12` | карточка с кнопками |
| `/post 12` | текст для канала со ссылкой |
| `/participants 12` | последние участники |
| `/export 12` | CSV со всеми участниками |
| `/finish 12` | подвести итоги досрочно |
| `/cancel 12` | отменить розыгрыш |
| `/winners 12` | победители и кнопки перевыбора |
| `/proof 12` | зерно и объяснение проверки |
| `/stats` | сводка |

Срок понимается как «3д», «48ч», «5.09 18:00» или «2026-09-05 18:00». Если
победитель не отозвался за `CLAIM_HOURS`, бот предлагает перевыбор: место
разыгрывается заново производным зерном, и это тоже проверяется.

## Запуск

```bash
cp .env.example .env          # BOT_TOKEN, BOT_USERNAME, OWNER_ID
pip install -e ../botkit      # каркас лежит рядом
pip install -e ".[dev]"
pytest -q
python -m giveaway run
```

В Docker — из каталога репозитория, потому что в образ нужен и `botkit`:

```bash
cd giveaway-bot
docker compose up -d --build
```

Проверка подписки требует, чтобы бот был администратором каждого канала. Если
он там не админ, Telegram не отдаёт состав — бот в этом случае пускает всех
и пишет об этом в лог: потерять участника хуже, чем пропустить неподписанного.

## Что внутри

* `draw.py` — зерно, билеты, выбор победителей, проверка. Чистые функции без
  ввода-вывода: их и тестировать легко, и переписать на любом языке для
  независимой проверки.
* `storage.py` — SQLite: розыгрыши, участники, победители. Подведение итогов
  идёт одной транзакцией, поэтому два одновременных `/finish` не дадут два
  разных списка победителей.
* `workers.py` — фоновая проверка сроков.
* `parsing.py` — разбор того, что организатор пишет с телефона.
* `subscription.py` — проверка подписки на каналы.

Каркас (настройки, хранилище, рассылка, воркеры, запуск) — в
[`botkit`](../botkit/).

## Тесты

```bash
pytest -q
```

Отдельно стоит смотреть `tests/test_draw.py`: там проверяется не «функция
что-то вернула», а свойства жребия — независимость от порядка участников,
чувствительность к составу, отсутствие двойных шансов у дубликатов, разброс
победителей по сотне зёрен и то, что подмена не проходит проверку.
