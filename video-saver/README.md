# video-saver — сайт для скачивания видео по ссылке

Человек заходит на сайт, вставляет ссылку на ролик и через полминуты забирает
файл. Ни входа, ни регистрации, ни пароля. Сервер скачивает видео к себе,
показывает проценты в реальном времени и отдаёт готовый файл — с перемоткой в
браузере и докачкой, если связь оборвалась.

Работу со ссылками делает [`yt-dlp`](https://github.com/yt-dlp/yt-dlp) —
открытый проект, который знает про тысячу площадок. Всё остальное здесь:
очередь, прогресс, лимиты, интерфейс.

## Что умеет

* Видео в mp4 (1080p, 720p, 480p) или только звук в mp3.
* Прогресс с процентами, скоростью и оставшимся временем — страницу можно
  закрыть, работа идёт на сервере.
* Просмотр прямо на сайте: плеер с перемоткой, без скачивания.
* Свой список закачек у каждого посетителя, чужие не видны.
* Ставится на домашний экран телефона как приложение; ссылкой можно поделиться
  из YouTube прямо в сайт.
* Лимиты и уборка старых файлов, чтобы диск не кончился.

## Чего не умеет — и не будет

Сервис берёт только то, что площадка и так показывает обычному посетителю.
В нём нет и не появится:

* обхода DRM и защищённых потоков;
* подстановки чужих cookie, входа в аккаунты, обхода возрастных барьеров и
  платных подписок;
* скачивания плейлистов и каналов целиком — только по одному ролику.

## Про авторские права — прочитайте, это важно

Скачивайте только то, на что у вас есть право: свои ролики, свободный контент,
материалы с разрешения автора. Права на чужое видео остаются у правообладателя,
и правила площадок никто не отменял.

Отдельно про то, что вы поднимаете **открытый** сервис. Отвечать за него будете
вы лично: жалобы правообладателей, письма от хостера и блокировки по IP со
стороны площадок приходят владельцу сервера, а не абстрактному сайту. Лимиты
ниже это смягчают, но не отменяют. Если сомневаетесь — сделайте сервис для себя:
не публикуйте адрес и закройте его на уровне прокси.

## Что нужно для запуска

**Железо.** Обычный VPS: 1–2 ядра, 2 ГБ памяти, диск от 40 ГБ, безлимитный или
щедрый трафик. У российских хостеров (Timeweb, Selectel, Beget, Reg.ru) это
200–500 ₽ в месяц, у зарубежных (Hetzner, Contabo) — примерно столько же.

Считайте по нагрузке: ролик на 10 минут в 1080p весит около 150 МБ, и он же
уходит посетителю. Сто скачиваний в день — это 15 ГБ трафика в день и около
полутерабайта в месяц. Диск нужен не под всё сразу, а под то, что лежит
одновременно: при хранении 4 часа и десятке закачек в час хватает и 20 ГБ.

**Программы.** Только Docker и Docker Compose. Python, ffmpeg и yt-dlp приедут
внутри образа.

**Домен.** Нужен, если хотите HTTPS и человеческий адрес вместо `http://IP:8080`.
Любой регистратор, 200–1000 ₽ в год.

## Установка

```bash
git clone <этот репозиторий>
cd Cloud-codes/video-saver
docker compose up -d --build
```

Сайт поднимется на `http://адрес-сервера:8080`. Данные лежат в `./data` рядом с
проектом: база задач и скачанные файлы. Каталог примонтирован в контейнер, так
что обновление образа их не теряет.

### Домен и HTTPS

Сделайте `A`-запись домена на IP сервера, откройте порты 80 и 443 и запустите
вторым файлом:

```bash
VSAVER_DOMAIN=video.example.com \
VSAVER_EMAIL=you@example.com \
docker compose -f docker-compose.yml -f docker-compose.https.yml up -d --build
```

Caddy сам получит сертификат Let's Encrypt, сам его продлит и сам переведёт
`http` на `https`. Порт 8080 наружу больше не смотрит.

Вместе с прокси включается `--behind-proxy`: без него лимит частоты считал бы
всех посетителей одним человеком, потому что в сокете сидел бы адрес Caddy.
Включать этот флаг **без** прокси нельзя — заголовок `X-Forwarded-For`
подделывается одной строкой в curl, и лимиты перестают работать.

## Лимиты

Это то, чем открытый сервис заменяет пароль. Без потолков диск и трафик
кончаются за пару дней, а счёт приходит вам. Все значения меняются в
`docker-compose.yml`, менять их лучше по одному.

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `--per-hour` | 10 | Задач в час с одного адреса |
| `--per-ip-active` | 2 | Одновременных закачек с одного адреса |
| `--queue-length` | 40 | Общая длина очереди; дальше «сервис занят» |
| `--max-size` | 2 ГБ | Потолок размера файла |
| `--max-duration` | 180 мин | Потолок длительности ролика |
| `--disk-quota` | 40 ГБ | Сколько места сервис готов занять |
| `--keep-hours` | 4 | Через сколько часов файл удаляется |
| `--workers` | 2 | Сколько закачек идёт одновременно |

Размер проверяется дважды: сначала по тому, что обещала площадка, потом по
реальным байтам — обещание бывает враньём, и закачка обрывается на превышении.

## Обновление yt-dlp

**Это обязательно и регулярно.** Площадки меняют разметку и форматы, и
позавчерашний `yt-dlp` в какой-то день просто перестаёт качать. Раз в пару
недель:

```bash
docker compose build --no-cache && docker compose up -d
```

Чтобы не помнить об этом, поставьте в `crontab -e` на сервере:

```
0 5 * * 1 cd /path/to/video-saver && docker compose build --no-cache && docker compose up -d
```

## Присмотр за сервисом

Веб-админки нет намеренно: меньше кода и нечего взламывать. Всё из терминала по
SSH.

```bash
# что в очереди, кто поставил, сколько занято на диске
docker compose exec vsaver python -m vsaver jobs --data /data

# снести одну задачу
docker compose exec vsaver python -m vsaver purge --data /data --id 1a2b3c4d5e6f7890

# снести всё старше двух часов
docker compose exec vsaver python -m vsaver purge --data /data --older-than 2

# скачать ролик прямо в терминале, без очереди и сайта
docker compose exec vsaver python -m vsaver get https://example.com/video --out /data
```

## Как это устроено

```
vsaver/
  urls.py        проверка ссылки: схема, приватные адреса, лишние параметры
  limits.py      потолки: частота, очередь, размер, длительность, диск
  downloader.py  обёртка над yt-dlp: формат, прогресс, отмена, разбор ошибок
  store.py       SQLite с задачами и файлы рядом
  jobs.py        очередь: работники, прогресс, отмена, восстановление
  server.py      HTTP: API, поток прогресса, отдача файла с Range
  web/           страница: HTML, CSS, JS без единой библиотеки
```

Три места стоит знать отдельно.

**Проверка ссылки — не формальность.** Ссылку присылает посторонний, а идёт по
ней сервер, изнутри сети хостера. Поэтому имя разрешается в адреса заранее, и
если хоть один адрес непубличный, ссылка отклоняется целиком: иначе сайт
превращается в инструмент, которым любой прохожий стучится по внутренней сети
VPS и в службу метаданных облака, где лежат ключи доступа (SSRF).

**Прогресс через Server-Sent Events.** Обычный HTTP-ответ, который не
закрывается. Работает через любой прокси и переживает спящий экран телефона
лучше веб-сокета, а кода требует втрое меньше.

**Отдача файла с `Range`.** Без неё плеер не перематывает видео, а оборванная
закачка начинается с нуля. Для сайта про видео это половина смысла, поэтому
разбор диапазона и ответ `206` написаны руками.

Задачи живут в SQLite на диске, а не в памяти процесса: перезапуск сервера не
теряет очередь, недоделанные задачи встают в неё обратно.

## Разработка

```bash
pip install -e ".[dev]"
ruff check .
pytest -q
python -m vsaver serve --port 8080 --data ./data
```

Сети в тестах нет: `yt-dlp` везде подменён заглушкой из `tests/conftest.py`,
которая умеет рапортовать прогресс, падать и зависать. Проверяется наш код —
очередь, лимиты, маршруты и отдача файла, — а не чужие площадки, которые
отвечают по-разному в зависимости от дня недели.

## Отступление от правил репозитория

Остальные проекты здесь обходятся стандартной библиотекой. Этот — нет: у него
есть зависимость `yt-dlp` и системный `ffmpeg`. Причина простая. Разбирать чужие
видеоплощадки своими руками бессмысленно (они меняются каждый месяц), а половина
такой работы состояла бы в обходе чужой защиты, чего мы делать не собираемся.
`ffmpeg` нужен, потому что YouTube и подобные отдают видео и звук раздельно —
без склейки получилось бы немое кино.
