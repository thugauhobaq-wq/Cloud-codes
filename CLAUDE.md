# Заметки для следующей сессии

## Где сейчас работа

Пять Telegram-ботов и каркас к ним, всё смёржено в `main`:
`booking-bot`, `shop-bot`, `leadmagnet-bot`, `giveaway-bot`, `freelance-parser`,
плюс `botkit` (каркас и генератор) и `botfactory`.

Развёртывание описано в [`DEPLOY.md`](DEPLOY.md), подготовка чистого сервера —
[`server-setup.sh`](server-setup.sh).

## Что проверено вживую

Арендован тестовый VPS (Timeweb, Москва, Ubuntu 24.04, KVM, 2 ГБ).
`server-setup.sh` отработал на нём целиком: Docker, фаервол, вход только по
ключу, подкачка. На этом сервере запущен `booking-bot` с настоящим токеном —
отвечает на `/start`, показывает услуги из `seed`.

Реквизиты сервера сознательно не записаны: репозиторий публичный.
Спросите пользователя, если понадобится адрес.

## Чего сделать нельзя (проверено, не гадать)

- **Telegram недоступен** из окружения разработки: `api.telegram.org` закрыт
  политикой прокси (403 на CONNECT). Живую проверку бота делает только
  пользователь; мы разбираем по его логам и скриншотам.
- **Исходящий SSH закрыт** — на любой хост, не по белому списку. Зайти на
  сервер пользователя из сессии нельзя.
- **Биржи фриланса закрыты** той же политикой, `freelance-parser` вживую здесь
  не запустить (`kwork.ru`, `fl.ru`, `freelance.habr.com`, `weblancer.net`).
- **Docker Hub недоступен**, образы тянутся через `mirror.gcr.io`; сборки в
  песочнице требуют базового образа с CA прокси и `--network=host`.

## Что обсуждалось и ждёт решения

1. **Автообновление на сервере** (выбранный вариант «A»): таймер раз в минуту
   делает `git pull` и `docker compose up -d --build`, отчёт о результате
   уходит владельцу в Телеграм. Секретов нигде не хранится. Не написано.
2. **Деплой через GitHub Actions** (вариант «B») — отвергнут для этого
   репозитория: ветки `claude/**` вливаются в `main` автомёржем без ревью
   (`.github/workflows/auto-pr.yml`), значит секрет с ключом от сервера
   прочитает любой будущий workflow. Если делать — только из приватного `ops`
   и с ключом, ограниченным `command=` в `authorized_keys`.
3. Остальные боты на тестовый сервер — не ставились, нужен свой токен каждому.
4. `.env` под реального заказчика вместо демо-барбершопа — не делалось.

## Договорённости по коду

- Интерфейс и комментарии — по-русски, тексты пишутся для владельца бизнеса,
  а не для программиста.
- Комментарий объясняет причину решения, а не пересказывает код.
- Тесты проверяют свойства и поведение при отказах, а не «функция что-то
  вернула». Ориентир — `giveaway-bot/tests/test_draw.py`.
- В документации отдельно перечисляется, что проверено вживую, а что нет.
